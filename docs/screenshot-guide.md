# Baixora screenshot slots

The site ships with five pt-BR product captures. Each one is a real capture of the
extension UI on a public TikTok page, with a marketing label, not a mock. The short drama
page uses a descriptive panel instead of a capture because there is no short drama
screenshot in the current set.

PNG sources live in `src/assets/screenshots/` and are **not** published. The WebP files in
`public/images/screenshots/` are generated by `npm run screenshots` and are what the site
ships.

## Generating the WebP files

```bash
npm run screenshots
```

The script uses Sharp with WebP quality 85 and writes the five outputs without resizing
or cropping. It replaces the existing WebP files in place.

## Rules

- Use real extension UI on a public TikTok page. Do not mock the interface.
- Remove or mask personal data, account handles, and anything you do not have permission
  to publish. The current `creator-profile` capture masks the handle but keeps the public
  profile photo and content.
- Keep the native dimensions of the capture. Update `width` and `height` in
  `src/data/screenshots.ts` and `scripts/check-site.mjs` if a replacement has different
  dimensions.
- Keep the alt text and caption accurate. If the UI or label changes, update the registry.
- **The current captures are pt-BR** and use the labels `Download único`,
  `Lista de pesquisa`, `Lista de exploração`, and `Painel do criador`. Do not add captions
  saying the product is English-only.
- Do not ship screenshot PNGs from `public/`; the check script fails if it finds one.
- Do not create a fake short drama screenshot. If a real capture is added later, add a
  `drama` entry to the registry and use `ProductShot` on the short drama page.

## Replacing a file

```bash
# Example: replace the bulk/search capture with a new pt-BR PNG
cp ~/captures/baixora-search-ptbr.png src/assets/screenshots/search-list.png
npm run screenshots
npm run verify
```

If the filename changes, update the matching `base` value in
`src/data/screenshots.ts`. Rebuild after generating; the check-site script verifies the
five expected WebP files and their dimensions.
